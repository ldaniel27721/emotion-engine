## 一、裁定内容

| # | 裁定 |
|---|---|
| **①** | **建库是必须的** —— 不能让大肥鱼每次现解析情绪词再反应，那样**会不准** |
| **②** | **离线查表，运行时不做解析** |
| **③** | 词库只需两列：**【释义】+【大类】** —— 不需要精确 PAD 坐标 |
| **④** | **大类只用来【限制方向】**（八型），不限定到具体点 |
| **⑤** | **强度只分【强烈 / 不强烈】二分**；不强烈的**模棱两可**，**开放给用户调教** |
| **⑥** | 细分辨别**交给模型**（大肥鱼背后是同源 LLM，它能自己判） |
| **⑦** | **释义 ≤20 字** |

**设定者原话**：
> 「这几百个词建库是必须的，如果每次都让大肥鱼先解析然后再对情绪做出反应我感觉有些会不准。」
> 「库秩需包含词的释义和大类即可。」
> 「大肥鱼因为套的模型和你一样，所以其实情绪类别只需要分出大类限制方向即可，
> 我刚刚想了想比较除了是否强烈的情绪外，其他没那么强烈的情绪其实比较模棱两可，
> 这个其实可以开放给用户去调教。」
> 「大多数情绪体验是模棱两可的**交由模型自行判断即可**。」

## 二、⭐ 两轴正交（本规格的核心）

**词库不是一套分类，而是**两根正交的轴**：**

| 轴 | 回答什么 | 来源 | 例 |
|---|---|---|---|
| **主题轴**（19 类） | 这个词讲的**是什么场景/对象** | 设定者 2026-10-10 给的骨架 | 自我评价类 · 人际互动类 · 目标相关情绪 · 社交场景 · 生理反应 |
| **方向轴**（12 类） | 这个情绪**往哪走** | Emotion-Feelings 体系 | 愤怒 · 悲伤 · 恐惧 · 爱与联结 · 平静 |
| **八型** | 方向的**具体取值** | Mehrabian 八型 → A1 球体方向 | `Hostile (−,+,+)` · `Anxious (−,+,−)` |

**⭐⭐ 一个词同时有主题和方向，两者不冲突：**
```
「丢脸」  主题 = 自我评价类    方向 = Remorse → Anxious (−,+,−)
「镇定」  主题 = 平静与满足    方向 = Calm    → Relaxed (+,−,+)
```

## 四、`kind`：情绪 vs 知觉（设定者的关键区分）

**设定者原话**：
> 「受伤的话它更想一种知觉，它更像是**体验情绪的前置物和副产物**，譬如自卑后感到受伤，
> 因受伤而感到怨恨，**受伤这个其实是种知觉**。」

**判据（语法形态）**：

| | 判据 | 例 |
|---|---|---|
| **`perception`** | 词形是**被动的、他者施加的**（被/受/遭/难/感），或是**躯体感受** | 委屈 · 心寒 · 受伤 · 被冷落 · 饥饿感 · 疼痛难忍 |
| **`emotion`** | 词形是**主动的、自发的状态** | 愤怒 · 恐惧 · 高兴 · 后悔 · 孤独 |

**⭐⭐ 数据自己印证了这条**：英文词表 `Hurt–betrayed` 全族都是被动式
（`accused` `blamed` `criticized` `mistreated` `victimized` `wounded`），
中文同理（`抱屈` `冤枉` `丢脸` `难堪` `心寒` `心酸` `辛酸`）。

**词库里的分布：`emotion 560 / perception 39`**

**⭐ perception 散在 9 个主题里，不是独立一类 —— 这正说明它是"前置物"：**
```
生理反应 11 · 自我评价类 10 · 悲伤 6 · 孤独与疏离 4 · 愤怒 3 · 恐惧 2 · 爱与联结 1 · 社交场景 1 · 无力与绝望 1
```

## 五、`intensity`：只两档

| 值 | 判据 | 词数 |
|---|---|---:|
| `strong` | 释义含「极」「非常」「强烈」「深切」「难忍」；或词本身是极端形态（暴怒 · 狂喜 · 万念俱灰） | 84 |
| `mild` | **其余全部**，含轻微/隐约/些许一律落这里 | 515 |

**⭐ 不设第三档 —— 模棱两可是【预期结果】，不是缺陷。**

## 六、完整闭环（词库在其中的位置）

```
                  ┌──────────────────────────────────────┐
事件 ──→ 定义事件 │ 词库（599 词：释义 + 主题 + 方向 + 强弱）│ ← 本规格
        （正/负/  │   · 只【约束方向】，不精确定位          │
         中性 +   │   · 模棱两可区：交给模型                │
         强烈度） └──────────────────────────────────────┘
                            ↓
                   知觉（受伤 / 被冷落 / 饥饿感…）   ← 前置物，不是情绪
                            ↓
                   AI 直觉判断（同源模型）           ← 模棱两可的交给它
                            ↓
                   ┌──────────────────────┐
                   │ 情绪模型 A1 球体 + A2 动力学 │ ← r 由 χ² 分布给
                   └──────────────────────┘
                            ↓
                     情绪输出 + 行为
                            ↓
                      用户体验 → 用户反馈
                            ↓
                   ┌──────────────────────┐
                   │ μ 慢漂移（#43）        │ ← ⭐ 反馈驱动的学习
                   └──────────────────────┘
```

**⭐⭐ 而「一千个读者有一千个哈姆雷特」在这里有精确位置：**
**同一个事件 + 不同 μ（底情绪）→ 不同情绪反应。这不是 bug，是 A3 定的 μ 角色化。**

## 七、数据来源与如何复现

| 来源 | 提供 | 文件 |
|---|---|---|
| **605 词表** | **主题轴**（19 类） | `persona/reference/情绪词汇表.md` |
| **Emotion-Feelings** | **方向轴**（10 类 + Calm），10 大类 × 3 强度档 | `E:\dsh\Emotion-Feelings(1).pdf` |
| **EmotionWordsChecklist** | 37 个细族（族标题自带两个近义代表词） | `E:\dsh\EmotionWordsChecklist(1).pdf` |
| **R&M 1977 Table 4** | 151 词 (P,A,D) 实测坐标 | `papers/EvidenceforaThree-factorTheory.pdf` |

**复现链：**
```bash
py -3 scripts/pdf-extract.py <pdf> <out.txt>              # 普通文本
py -3 scripts/pdf-formula-extract.py <pdf> <outdir>       # ⭐ bbox 排序（多列表必须用这个）
node scripts/parse-emotion-vocab-605.js                   # 605 表 → JSON
node scripts/parse-emotion-feelings.js                    # Emotion-Feelings → JSON
node scripts/parse-emotion-checklist.js                   # Checklist → JSON
node scripts/validate-rm1977.js <table4.json>             # R&M 151 词校验
node scripts/merge-cn-lexicon.js                          # 方向映射合并 + 校验
node scripts/assemble-lexicon.js                          # 两轴组装 → 最终词库
```

**⚠️ 方法教训（值得记）：**
- **多列表 PDF 必须用 bbox 抽取器。** `get_text()` 会把族标题排到文件末尾、把它的词错归给前一个族。
- **英文 R&M 表的负号在低分辨率下易丢**，必须用【独立锚点】交叉校验。
