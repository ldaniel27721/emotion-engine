## 3. ⭐⭐⭐ 本会话最重要的三条裁定（新会话必须先读）

### ① 这是【情绪的衰减】，不是记忆系统
```
设定者原话：「这个东西针对的是【情绪的衰减】而不是【记忆的问题】，
             大肥鱼你要清楚别绕进去了」

⇒ 问的不是「这个事还记得吗」
   而是「这个事带来的【情绪】，现在还剩下多少」
⇒ memory.js 里方法名是 residual（情绪残余），不是 retrievability
```

### ② S 挂【评价层】
```
S = S0 · (1 + k · intensity)      intensity 来自评价层（模型判断）
条目 = { turn, at, summary, emotion, intensity }
       —— summary / emotion / intensity 三者都由模型或评价层给，模块不做判断
```

### ③ 情绪【不分对象】，记忆【按人分桶】
```
✅ 引擎只有【一条 E】—— 不做"对 A 的情绪"/"对 B 的情绪"
✅ 但记忆要能记住"每个人说了什么" ⇒ 按 senderId 分桶
⭐ 两者作用域【刻意不同】，不是疏漏
```

## 4. 情绪衰减公式 v1（核心成果）

```
E_t − μ = Σ_i ΔE_i · exp( −(t − t_i) / S_i )
          S_i = S0 · (1 + k · intensity_i)      ← S 挂评价层

依据：ρ^Δt = exp(−Δt·λ)，λ = −ln(0.927) = 0.075802
⇒ 情绪衰减（A2 的 ρ）与 记忆衰减（SuperMemo）【同族】
⇒ 差别只在 ρ 是"全局"还是"逐事件"
⭐ A2 是 v1 在强度全同时的特例 —— 已数值验证，差 1.110e-16

⚠️ 重要后果：v1 之下【递推写法失效】⇒ 必须保留事件账本
⇒ 情绪账本从「附加模块」变成「引擎的必需组件」
验证脚本：demo/derive-emotion-decay.js
```
