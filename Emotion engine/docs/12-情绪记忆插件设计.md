> 比如自建一个简易的情绪记忆插件（**时间 + 轮次 + 事件 + 情绪**）通过每轮次注入

## 0. 为什么现有的东西不够

```
现状：
  E 层（快变量）：会叠加、会留痕，但按 ρ^age 指数消失 ⇒ 半衰期 9.14 轮
  μ 层（慢变量）：不自动记 —— 必须显式调 drift()

⇒ 结果：模型【短期会记，长期会忘】。见 docs/11。
⇒ ⭐ 而且更根本的问题：当前设计里【根本没有一处存着"发生过什么"】。
   E 只存"情绪的当前值"，不存"哪件事造成的"。
```

**⭐ 缺的不是衰减机制，是【事件本身】没有落点。**

## 1. 条目格式（设定者给的 4 字段 + 本鱼建议加的 2 个）

```js
{
  // ── 设定者提出的 4 个 ──
  at:       '2026-10-13T09:15:00+08:00',  // 时间（真实墙钟）
  turn:     18,                            // 轮次
  event:    '用户说「你今天有点可爱」',      // 事件（自然语言摘要）
  emotion:  { direction: 'Caring', octant: 'Dependent',
              valence: 0.72, r: 0.94, E: [0.58, 1.06, -0.52] },

  // ── 本鱼建议加的 2 个 ──
  eventKey: '被夸奖',    // ⭐ 事件类别：用于 h(n) 计数与聚类检索
  importance: 0.85,      // ⭐ AET 的一级评价变量，检索打分要用
}
```

**⭐ 为什么加这 2 个：**
```
eventKey  —— 没有它，同类事件无法聚类（"第 5 次被夸"这种统计做不出来）
importance —— genagents 的记忆流打分是 recency + importance + relevance，
              而 importance 我们【已经算出来了】（AET 一级评价），白捡的
```

## 2. 三处用途（**关键：分工必须写清，否则会双重计入**）

```
                    ┌──────────────────────────────┐
                    │   情绪记忆库（落盘）           │
                    └───────┬──────────┬───────────┘
                            │          │
          ┌─────────────────┘          └──────────────────┐
          ↓                                                ↓
  ┌───────────────────┐                        ┌───────────────────┐
  │ a) 注入 LLM 的上下文 │                        │ b) 喂 μ.drift()    │
  │    管"当下说什么"    │                        │    管"长期变成什么样" │
  └───────────────────┘                        └───────────────────┘
                            │
          ┌─────────────────┘
          ↓
  ┌───────────────────┐
  │ c) eventKey 计数    │  ← 已有，用于 h(n)
  └───────────────────┘
```

**⚠️ 分工铁律（防双重计入）：**
```
· 注入 LLM  ⇒  只影响【表达层】用哪些话，【不改变引擎的 E】
· 喂 μ.drift ⇒  只影响【底情绪】的慢漂移
· ⭐ E 只由 ΔE 驱动 —— 记忆永远不直接改 E。
   （否则同一件事会被算两遍：一次经注入影响表达，一次经记忆影响 E）
```

## 3. ⭐ 本鱼要提的一个设计问题：**两个时间轴**

**设定者给的是「时间 + 轮次」两个都有 —— 这个直觉是对的，而且很重要。**

```
引擎的 ρ      →  按【轮次】衰减（B4 已裁定：ρ 的轴 = 对话轮次）
记忆的 recency →  应该按【真实时间】衰减

⭐ 两者【不应】一致，因为：
   · 一晚上连聊 100 轮   ⇒ 轮次多，但真实时间只过了几小时
   · 隔一周才回一句      ⇒ 轮次少，但真实时间过了一周

⇒ 对陪伴型角色，"一周没说话"应该比"上一轮的 100 轮前"更该被淡忘。
⇒ ⭐ 建议：检索打分用【真实时间】的衰减，
        而引擎内部的 ρ 保持按轮次（不动 A2）。
```

**⚠️ 但要诚实标注：真实时间衰减的系数【没有文献依据】，需要工程标定。**
（genagents 的 0.995/步 是"步"，不是"秒" —— 量纲不可直接移植。）

## 4. 检索与注入

### 4.1 打分（genagents 的三项，改一项）

```
score = w_r · recency + w_i · importance + w_rel · relevance

recency    = exp(−Δt / τ)        ⭐ 用【真实时间】Δt，τ 待标定
importance = 记忆里存的 AET importance（1–10 或 0–1）
relevance  = 当前事件向量 与 记忆情绪向量 的余弦相似度

⚠️ 与 genagents 的差异：它用 0.995^steps（离散步），我们用 exp(−Δt/τ)。
   理由：陪伴型的"隔多久"是墙钟时间，不是步数。系数需工程标定。
```

### 4.2 注入格式（⚠️ 用自然语言，不用 JSON）

```
【你还记得的】
· 昨天 ta 没理你 → 你当时挺难受的
· 刚才 ta 说中了你的心事 → 你嘴上不认，但心里软了
· 三天前 ta 夸过你一次
```

**⭐ 三条设计规则：**
```
① 【相对时间词】不用时间戳 —— "昨天" / "刚才" / "三天前"
   （LLM 对 ISO 时间戳没有直觉，对"昨天"有）
② 【当时】的情绪，不是现在的回溯解读 —— 标"你当时…"
   ⚠️ 人回忆时会 reappraisal（重新评价），但这个要单独设计，先不做
③ 条数上限（建议 top-3 ~ top-5）—— 多了挤上下文，且"全记得"不像人
```

## 5. ⚠️ 要小心的 5 个点

| # | 风险 | 处置建议 |
|---|---|---|
| **①** | **注入量失控** | 硬上限 top-K（建议 3–5 条）；按 score 截断；单条限长 |
| **②** | **三个时间尺度混用** | ρ（轮次，9.14 轮）· recency（真实时间）· μ 漂移（长期）—— **明确分开，别共用一个系数** |
| **③** | **"当时的情绪" vs "现在的解读"** | 先只存/注入【当时】的；reappraisal 留作后续 |
| **④** | **遗忘曲线** | 必须有真的遗忘（否则不像人 + 挤爆上下文）；建议 score 低于阈值即不再注入 |
| **⑤** | **跨会话持久化** | 落盘（JSONL 最简）；这正是 #43「记忆是 μ 唯一载体」的物理载体 |

## 7. ⭐ 设定者的三点裁定（2026-10-13）

| # | 问题 | 裁定 |
|---|---|---|
| **①** | 遗忘曲线用什么 | **SuperMemo** 的遗忘曲线 —— https://supermemo.guru/wiki/Forgetting_curve |
| **②** | 记忆要不要跨会话 | **不需要** —— 本会话保留即可 |
| **③** | 「记仇/记爱/记恨」是什么 | ⭐ **它们只是形容人格特质的**；影响的是**漂移**。<br>真正的作用是：**大肥鱼更容易记住让自己体验强烈情绪的事件** |

### 7.1 ⭐ 取回的遗忘曲线（原文）

> 出处：Wozniak, Gorzelanczyk, Murakowski (1995)，经 SuperMemo 站原文核对

```
R = exp(−t / S)

  R - probability of recall (retrievability of memory)
  S - strength of a memory trace (stability of memory)
  t - time
```

**原文两句关键话（逐字）：**
> "if all words are reviewed again, **their stability will increase** and retention
>  time will be extended. This is used in spaced repetition"

> "Forgetting is exponential, however, **superposition of forgetting rates for
>  different stabilities** will make forgetting follow the power law."

### 7.2 ⭐⭐ 与裁定 ③ 的对接

**情绪强度该进 `S`（稳定性），不是进 `R`：**
```
S 越大 ⇒ 衰减越慢 ⇒ 记得越牢
"更容易记住让大肥鱼体验强烈的情绪" ⇒ S = f(当时的情绪强度 r)
```

**⚠️ 诚实标注：**
```
R = exp(−t/S)          ← SuperMemo 的（有出处）
S = S0 · (1 + k·r)     ← ⚠️ 【本项目设计】，文献【没有】这个公式
```

### 7.3 裁定 ③ 的落地形式

```
"记仇 / 记爱 / 记恨" 【不是新状态】，而是【同一个事件被记得多牢】的乘数：

  S = S0 · (1 + k·r) · trait(vSign, toObject)

  traits = { neg: 记仇, pos: 记爱, object: 记恨 }

⇒ ⭐ 于是它们【自动影响漂移】：
   记仇型角色 ⇒ 负性事件 S 更大 ⇒ 检索权重更高 ⇒ 喂给 μ.drift() 的分量更大
```

## 7.4 ⚠️⚠️ 定性更正（设定者 2026-10-13，最重要的一条）

> **设定者原话：**
> 「关于这个记忆系统的一点就是，这个东西针对的是**情绪的衰减**而不是**记忆的问题**，
>  大肥鱼你要清楚别绕进去了。」

**⇒ ⭐⭐ 它不是一个"记忆系统"，是【情绪残余的账本】：**

```
问的不是「这个事还记得吗」
而是「这个事带来的【情绪】，现在还剩下多少」
```

**⭐⭐ 而这就接上了第二条更正：**
> 「S 那就挂评价层上，因为是评价得出结论的然后出的情绪」

```
事件 → 评价层 → intensity（情绪强度，模型判断）
       ↓
    录入：{ turn, at, summary, emotion, intensity }
       ↓
    S = S0 · (1 + k · intensity)          ← ⭐ S 挂评价层
       ↓
    R = exp(−Δturn / S)                   ← ⭐ 这是【情绪残余】
```

**⭐ 与引擎的 ρ 的关系（呼应设定者"遗忘曲线主要是解析 ρ 轮次问题"）：**
```
ρ  管「当下这一团情绪怎么散」（E 层，快变量）
R  管「历史上每个事件的情绪还剩多少」（情绪账本）
⇒ 同一条曲线，两个层次
```

**⭐ 实测数值（S0=30, k=4）：**

| intensity | S | 半衰期 | 情绪寿命（R→0.05）|
|---|---|---|---|
| 0.00 | 30.0 | 20.8 轮 | 90 轮 |
| 0.50 | 90.0 | 62.4 轮 | 270 轮 |
| 1.00 | 150.0 | 104.0 轮 | 449 轮 |

**⚠️ 由此得出一个反直觉但正确的行为：**
```
排序不是"越近越前"，而是"残余越高越前"。

实测：第 25 轮时
  [轮 1] i=0.95 S=144 ⇒ 残余 0.8465   ← 24 轮前的强情绪
  [轮10] i=0.05 S=36  ⇒ 残余 0.6592   ← 15 轮前的弱情绪
⇒ ⭐ 24 轮前的强情绪【排在前面】
```

## 7.5 ⭐⭐⭐ 最终规格（设定者 2026-10-13，覆盖此前全部设计）

> **设定者原话：**
> 「就是模型本身对事件的判断，然后把事件精简成某些提示词或者情绪词录入记忆系统，
>  打上时间戳或者轮次步数，**我们这个记忆系统只需要模型自己去提取关于这个事件的摘要和情绪就可以了，
>  我们不需要他们那种复杂的系统构造**。」

### 条目只有四样

```js
{ turn,        // 轮次步数
  at,          // 时间戳
  summary,     // ⭐ 事件摘要 —— 模型自己提取
  emotion }    // ⭐ 情绪词   —— 模型自己提取
```

### ⭐ 被删掉的（原文里"他们那种复杂的系统构造"）

| 删掉的 | 为什么删 |
|---|---|
| `S`（逐条记忆稳定性） | 不需要逐条算 —— 遗忘曲线在这里只用来**排序** |
| `S = S0·(1+k·r)` | 情绪强度是**模型判断**的，不是公式算的 |
| `kEmotion` / `kRecall` / `maxS` | 无复习机制，也就没有增益 |
| `traits`（记仇/记爱/记恨） | 设定者：这三条只是**形容人格特质**的 |
| **复习通道** | 设定者：「复习通道其实没那么重要，只要模型还留有记忆那**按关键词或者摘要触发即可**」 |
| **成功/失败双分支** | 设定者：「**在 AI 模型中失败几乎是不存在的**，因为模型靠的是记忆库（库里有就算有了）而不像人脑需要建立特定的电信号回路」 |
| `driftVector` | 第 2 步才需要，先不做 |

### ⭐ 遗忘曲线留在这里的唯一用途：**按轮次远近排序**

```
R(t) = exp(−λ · Δturn)
  λ 由「ρ 按轮次衰减」标定
  ρ = 0.927 ⇒ λ = −ln(ρ) = 0.07581 ⇒ 半衰期 9.14 轮
```

**⭐ 这正是设定者说的「遗忘曲线主要是解析 ρ 轮次问题」—— 与引擎同一个时间轴。**

### 检索 = 关键词 / 摘要触发

```
retrieve(nowTurn, hint)
  · hint 里的关键词与记忆的 keywords 匹配（中文 2-gram / 英文按词）
  · 命中的按 R 降序取 top-k
  · 一条都没命中 ⇒ 退回全体（仍按 R 排序）
  · R < minR(0.05) ⇒ 真遗忘，不再注入
```

### ⚠️ 一条对本鱼此前设计的更正

```
本鱼原以为 StrataGate 的 block_decay_lambda = 0.3 是"情绪记忆的遗忘曲线"，
设定者更正：「stratagate 的是【记忆简化路径】，就是我在第几轮应该还需要那些摘要
              或者提示方便记忆，也方便精简记忆占用的存储空间」

⇒ ⭐ 它是【存储压缩】，用途完全不同，不能直接搬。
   两个系统的用途对照：
     StrataGate    —— 上下文里该塞哪些摘要 ⇒ 省 token / 省存储
     本记忆插件    —— 让大肥鱼"记得"发生过的情绪事件 ⇒ 让行为带记忆
```

## 8. ✅ 已实现（`src/memory.js`，简化版）

```
类：EmotionMemory

  add({ turn, at, event, eventKey, emotion, importance, toObject })
  retrievability(entry, nowTurn)        R = exp(−(nowTurn − entry.turn) / entry.S)
  stabilityFor(r, vSign, toObject)      S = S0 · (1 + k·r) · trait
  score(entry, nowTurn)                 R × importance
  ranked(nowTurn)                       全体按分数降序
  retrieve(nowTurn, k, { rehearse })    top-k；rehearse=true 时把注入算作一次复习
  render(hits, nowTurn)                 自然语言注入文本
  driftVector(nowTurn)                  Σ R · 情绪向量（供 μ.drift）
  describe(nowTurn)                     审计用摘要
```

**参数与默认值：**

| 参数 | 默认 | 含义 |
|---|---|---|
| `S0` | 30 | 基准稳定性（轮）。R=0.5 时 t = S·ln2 ≈ **20.8 轮** |
| `kEmotion` | 4 | 情绪放大：r=1 的记忆 S 是 r=0 的 **5 倍** |
| `kRecall` | 0.5 | 每次被想起 ⇒ S ×1.5（间隔重复） |
| `minR` | 0.05 | 低于此可提取性 ⇒ **真遗忘**，不再注入 |
| `traits` | 全 1.0 | 记仇(neg) / 记爱(pos) / 记恨(object) |
| `maxS` | S0·(1+k)·max(traits) | 防反复想起导致失控 |

**数值行为（`demo/test-memory.js`，33 项）：**
```
r=0.10 ⇒ S=42   半衰期 29 轮   200 轮后 R=0.0085
r=0.50 ⇒ S=90   半衰期 62 轮   200 轮后 R=0.1084
r=1.00 ⇒ S=150  半衰期 104 轮  200 轮后 R=0.2636
⇒ ⭐ 强烈情绪的记忆【几乎不衰减】，平淡的早没了

间隔重复：S = 30 → 45 → 67.5 → 101.25 → 151.88 → 227.81（每次 ×1.5）
真遗忘：   S=10 时 R(30)=0.0498 < 0.05 ⇒ 不再注入
```

**注入示例（实际渲染输出）：**
```
【你还记得的】
· 早些时候 用户说「你其实很在意吧」 → 你当时特别软下来
· 方才几轮 用户语气重了 → 你当时特别生气
· 之前一阵 用户说「你今天有点可爱」 → 你当时有点开心
```

**⭐ 本会话保留** ⇒ 模块**不写文件**（无 `fs` 依赖）；`entries` 可序列化，但默认不落盘。

     实测渲染 3–5 条都清爽（见 demo/test-memory.js ⑧）

③ "记仇/记爱/记恨" 是否要【独立于 μ 漂移】的第三条通道？
   ⇒ ⭐ 不要独立通道。
     设定者原话：「这三条只是形容人格特质的，它会影响漂移，
     这三个记影响的是大肥鱼对于深刻情绪记忆，也就是说更容易记住
     让大肥鱼体验强烈的情绪及其事件」

     ⇒ 落法：它们【不是新状态】，而是【同一个事件被记得多牢】的**乘数**，进 S：
          S = S0 · (1 + k·r) · trait(vSign, toObject)
          traits = { neg: 记仇, pos: 记爱, object: 记恨 }

     ⇒ ⭐ 因此它们【自动影响漂移】——
        记仇型角色的负性记忆 S 更大 ⇒ 检索权重更高 ⇒
        喂给 μ.drift() 的分量自然更大。
        既满足"影响漂移"，又不引入第三套时间尺度。
